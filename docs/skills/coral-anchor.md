# Coral — Anchor Framework Client for Dart

> Interact with Anchor-based Solana programs from Flutter using IDL-driven code generation.

## Overview

Most Solana programs are built with the Anchor framework. Anchor generates an IDL (Interface Definition Language) file that describes every instruction, account, and type in the program. The `coral_xyz` package reads this IDL and lets you interact with the program without manually building instructions or serializing data.

Use `coral_xyz` when:

- The program you're integrating with uses Anchor
- You want type-safe instruction building from an IDL
- You want automatic account deserialization

Use raw `solana` + `dartus` when:

- The program is NOT built with Anchor (raw Rust, Pinocchio, etc.)
- You need fine-grained control over instruction encoding
- The IDL is unavailable or incorrect

## Quick Start

```yaml
dependencies:
  coral_xyz: ^0.1.0
  solana: ^0.31.0
```

```dart
import 'package:coral_xyz/coral_xyz.dart';
import 'package:solana/solana.dart';

// Load the program's IDL (from JSON file or asset)
final idlJson = await rootBundle.loadString('assets/idl/my_program.json');
final idl = Idl.fromJson(jsonDecode(idlJson));

// Create the program client
final programId = Ed25519HDPublicKey.fromBase58('YourProgramId...');
final client = RpcClient('https://api.devnet.solana.com');
final program = AnchorProgram(idl: idl, programId: programId, client: client);
```

## Core Concepts

### What is an IDL?

An IDL is a JSON file generated by `anchor build` that looks like this:

```json
{
  "version": "0.1.0",
  "name": "counter",
  "instructions": [
    {
      "name": "initialize",
      "accounts": [
        { "name": "counter", "isMut": true, "isSigner": false },
        { "name": "user", "isMut": true, "isSigner": true },
        { "name": "systemProgram", "isMut": false, "isSigner": false }
      ],
      "args": []
    },
    {
      "name": "increment",
      "accounts": [
        { "name": "counter", "isMut": true, "isSigner": false },
        { "name": "user", "isMut": false, "isSigner": true }
      ],
      "args": [
        { "name": "amount", "type": "u64" }
      ]
    }
  ],
  "accounts": [
    {
      "name": "Counter",
      "type": {
        "kind": "struct",
        "fields": [
          { "name": "count", "type": "u64" },
          { "name": "authority", "type": "publicKey" }
        ]
      }
    }
  ]
}
```

> **CRITICAL**: Always get the IDL from the program's official repository or by fetching it on-chain (`anchor idl fetch <program-id>`). Never hand-write an IDL — even small mistakes cause silent data corruption.

### IDL as a Flutter Asset

Store the IDL JSON in your Flutter project's assets:

```
assets/
  idl/
    counter.json
    vault.json
```

```yaml
# pubspec.yaml
flutter:
  assets:
    - assets/idl/
```

### Calling Instructions

```dart
// Call the 'initialize' instruction
await program.rpc.initialize(
  accounts: {
    'counter': counterPda.key,
    'user': wallet.publicKey,
    'systemProgram': Ed25519HDPublicKey.fromBase58(
      '11111111111111111111111111111111',
    ),
  },
  signers: [wallet],
);

// Call 'increment' with arguments
await program.rpc.increment(
  args: {'amount': 5},
  accounts: {
    'counter': counterPda.key,
    'user': wallet.publicKey,
  },
  signers: [wallet],
);
```

### Reading Account Data

```dart
// Fetch and automatically deserialize a Counter account
final counterData = await program.account.counter.fetch(
  counterPda.key.toBase58(),
);

print('Count: ${counterData['count']}');
print('Authority: ${counterData['authority']}');
```

> **WHY THIS MATTERS**: The Anchor IDL includes account discriminators and field schemas. `coral_xyz` handles the 8-byte discriminator automatically — you don't need to skip it manually like you do with raw `dartus`.

### Anchor Instruction Discriminator

Anchor uses an 8-byte discriminator for instructions too (first 8 bytes of `SHA256("global:<instruction_name>")`). The coral package handles this automatically when you call through `program.rpc.<method>`.

If you need to build the instruction manually:

```dart
import 'dart:convert';
import 'package:crypto/crypto.dart';

// Calculate the discriminator for "initialize"
final hash = sha256.convert(utf8.encode('global:initialize'));
final discriminator = hash.bytes.sublist(0, 8);
```

## Patterns

### Dynamic IDL Loading

For apps that interact with multiple programs:

```dart
class ProgramRegistry {
  final Map<String, AnchorProgram> _programs = {};
  final RpcClient _client;
  
  ProgramRegistry(this._client);
  
  Future<AnchorProgram> getProgram(String name) async {
    if (_programs.containsKey(name)) return _programs[name]!;
    
    final idlJson = await rootBundle.loadString('assets/idl/$name.json');
    final idl = Idl.fromJson(jsonDecode(idlJson));
    final programId = Ed25519HDPublicKey.fromBase58(idl.metadata.address);
    
    final program = AnchorProgram(
      idl: idl,
      programId: programId,
      client: _client,
    );
    
    _programs[name] = program;
    return program;
  }
}
```

## Common Mistakes

| Mistake | Why It Happens | Fix |
|---------|---------------|-----|
| Using wrong IDL version | Program upgraded, IDL not updated | Always pull fresh IDL from repo or `anchor idl fetch` |
| Missing `systemProgram` in accounts | Anchor requires it for init | Include System Program for any instruction that creates accounts |
| Forgetting `isMut`/`isSigner` semantics | Accounts must match instruction definition | Read the IDL carefully — mutable accounts need writable access |
| IDL `address` field doesn't match deployed program | IDL generated locally, not from deploy keypair | Verify IDL address matches `solana program show <ID>` |
